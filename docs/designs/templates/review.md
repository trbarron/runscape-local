## Comprehension

Record the reviewer's explanation of the system and any unanswered questions. Do not supply the
answer in the review prompt or substitute the author's own explanation for a fresh review.

## Findings

| ID | Severity | Source/document location | Finding | Resolution | Evidence |
|---|---|---|---|---|---|

Use Blocker / Major / Nit consistently. Separate source defects from inaccurate documentation
and proposals for future work. Mark rejected recommendations with rationale, not deletion.

## Readiness

State the actual result and its limits. A partial/source-only review is not a clean full review.
Record whether changes need a new review, whether the user authorized implementation, and the
first acceptance check an implementer should run. Never fabricate approval or completed stages.
